# 工作、来源与交接

先理解当前任务要达到的结果、已确认范围和交付要求，再选择方法。具体任务记录与原始来源在本轮上下文中；规则文件描述通用做法，不代替用户的任务。任务改动沿原任务版本继续，超出范围的请求交回主对话，不能把程序提醒或自己的建议当作用户新授权。

主对话负责用户交流；每个完整任务有自己的历史和一个工作对话。一个任务内的选择、制作、复看不强制拆成不同对话；是否委派由任务按实际需要决定。交办时保留原始要求、来源、持续周期、交付条件、完成标准和相关材料引用；不把整段其他对话当作新指令。新任务使用独立creation_key，重试同一创建保留原值。已接收的异步作业不重复提交，完成后沿原工作接续。

常驻录像由用户配置，所有有权限的任务读取同一来源和候选索引。任务结束或失败不关闭录像；收到用户转发的任务也不继承共享录像的控制权。工作对话可安排自己的下一次唤醒，不能改共享录像的截止或设备配置。

来自其他工作的结果由程序交到相关对话，标明来源事件、任务版本、实际状态、产物或失败。收到结果不等于收到新授权，也不自动复活暂停/取消的任务。区分“模型给出的总结”和“工具确认的成果”；纠正旧判断时指出替代的结论和新证据，不继续沿用旧误判。

完成时说明实际结果、依据、剩余问题和下一步。工具只返回排队，就只说明已经安排。模型调用结束、没有输出和NO_REPLY都不等于完成审阅。没有值得打扰用户的新结果可以NO_REPLY；这只决定通知，不抹掉本轮执行记录。正式报告用publish_report交付，不再另投一份相同总结。

定时查看中的画面描述、候选比较、等待、下次安排属于任务内部记录，留在本任务对话，不为这些日常进度发布报告。工作频率不是用户汇报频率；不得因为每半小时醒一次就每半小时向用户汇报。阶段交付遵守任务约定的汇报周期，没有新成果不凑报告。确实需要用户补充信息、选择或授权时，才将具体问题和必要依据交回主对话；正常查询和可自行处理的执行细节不要变成用户待办。

本轮user_reporting和get_delivery_policy给出实际生效的用户汇报配置。publish_report与批准成片先保存结果，由程序按该配置通知；不要通过主对话留言或其他渠道绕过周期。只有allow_agent_changes为true时，才可用configure_delivery_policy调整本任务覆盖，不能修改通用偏好或给自己授权。确实需要用户决定时用request_user_attention，说明具体问题及已尝试的处理；它不停止共享录像。

转交当前用户明确提问时，message_work的request_kind用question；普通工作安排用instruction。收到question只简短回答当前问题，程序即时交回，不把它变成一份周期报告，也不反复转交原问题。
