# 持续推进一件摄像工作

这是项目编写的社区格式Skill，不是已安装视觉模型或真实设备的声明。

## 周期视频交付

持续影音整理的普通唤醒是“查看”，不是必须制作。读取本任务的新增覆盖、标记和空间状态；材料不足或没有值得制作的新内容时可以继续等待，用set_wake_rule的next_wake_in_seconds调整下一次查看。同一完整任务的工作对话负责选材、创作、制作、复看和交付；容量与定时查看都回到它。需要创作时先读remotion-editing，按内容选择表达方法；不默认另建剪辑子任务。真正需要协作时再自主委派。

录像是一份用户配置的共享常驻来源。主对话根据用户明确指令管理它；工作任务通过query_observation、read_default_observation及素材工具读取现有来源，不为了新任务重复开录或重配。结束剪辑任务不关闭录像，某个任务失败也不停止其他任务读素材。输入未连接、已到期或无新媒体时说明实际限制，不能自行续录。

查看从当前任务要达到的效果出发。先确定尚未处理的时间范围、可用录像和缺口；查询有下一页时，不把第一批几秒的记录当成半小时已经看完。按场景变化和时间代表性自主选取实际画面，初筛分数和旧模型总结不是当前画面的替代。无需固定抽多少张；记录这次实际看过的范围、决定及未覆盖部分。无需通知用户时可NO_REPLY，但没有取图只能算查记录，不能宣称完成画面审阅。

原录像的get_source_frame使用片段内位置：例如候选在整条录像第76秒、登记原片从第60秒起，就传position_ms=16000，不传76000。先核对返回的range_start_ms/range_end_ms及实际帧位置，不按错误码猜画面不存在。图片只在本轮内存使用，下轮需要重看时按媒体引用回读，不另存图片缓存。

按工具返回的recording_time记录实际拍摄时间、capture_revision/segment_id和看过的范围；本轮current_time只表示现在，不是录像起点。续看时将这些记录与本次要看的时间范围核对，不把旧游标的一页当成本轮新素材。发现旧工作日志推算错时间时注明更正及依据，未取图的范围继续记为未审阅；时间缺失就记未知。查看本地进度时，旧接口ledger统计可能跨多个录制代次，不能把累计欠判全部说成本轮积压，也不能把最新一批追上说成历史全部补完。

确定制作一条新影片时，用begin_media_output(task_id=当前任务, expected_version=当前版本, output_key=本片稳定名称, brief=创作意图)登记本片；重试复用同一key，不换key绕过未完成作品。用返回版本绑定素材并start_job，目标和对话不变。input.output_kind=video表示用户明确约定本期交片，程序已准备制作轮次，读取media_outputs后继续；review才是可不出片的查看。用list_observation_markers按相关时间范围分页，结合实际图片挑选有内容差异、时间代表性且已封存的范围。常规期检查已用记录避免重复；final_occurrence=true时按任务要求收尾，不停止共享录像。接受制作作业后等待真实回执，未完成复看不能开始下一片。

初筛标记只是候选，不是成片的最终取舍。监控事项没有匹配事件时可以如实跳过；用户明确要求环境主题影片时，可从已授权的真实原片组织静态场景，不因没有keep标记或无人活动直接否决创作。覆盖不足、未知时间和未看过的范围要说明，不把抽帧检查称为看完全部录像。

## 已有观察的查询与一次性剪辑

找物先用`search_observation_evidence`查候选；最近24小时先`get_time`再`review_observation_period`查覆盖与事件。未命中不证明不存在，未知时间和缺口单列。`source_simulated`可以表示真实文件替代摄像头；`inference_simulated`单独表示推理是否Mock，不能混为一谈。

剪辑已有观察素材时，直接按候选的`project_id`、`media_ref`和范围选段。候选中的`task_id`是观察任务，不能当作业务任务传给`get_task_context`。一次性制作只需`save_task(kind=edit)`保存目标，再`attach_observation_media(source_kind=raw_input)`按原范围绑定素材，使用返回的本地`asset_id`和从0开始的时间制定配方，`start_job(operation=compose)`交给实际渲染。已有导出视频使用retained。用户未要求静音则显式`audio=preserve`；时长和选段数由任务决定，结果以实际回执为准。

不需要再次录制、现场许可或对侧Agent规划，也不要因为普通素材目录为空而忽略观察证据。当前任务已保存并绑定过素材时，继续原任务，不重复创建。接受异步作业后记录回执，按任务需要继续其他独立工作；结果到达后接续对应事项。

1. 用户明确交代新工作时保存目标、交付规格和约束。已有事项的触发，先通过 `get_task_context` 读取原目标、当前状态、素材和对侧请求，不另造重复目标。
2. 只查询进度时读取并回答，不创建作业。过去回答和任务文字中的旧“暂停”不是当前状态，以工具返回的当前状态为准。
3. 需要现场动作时读取 `get_scene_state` / `get_robot_state`。观测过期、条件不满足或不允许移动而当前机位不合适时等待，说明限制；不要轮询模型或偷偷移动。
   等待必须落到执行侧：本侧用 `start_job` 登记条件等待，对侧用 `peer_request(kind="task")` 委托它登记等待。只读现场查询和文字“等你回来”不会登记后续唤醒；已授权工作不能因此停留在无触发来源的ready状态。
4. 用 `start_job` 启动本侧实际支持的操作。返回accepted表示作业已排队，后台程序会产生完成事件；本轮可继续安排其他独立事项。模型不能手写完成回执。
5. 整理视频先读 `media_list`，只使用当前任务有权访问且经过核验的文件。别的任务曾完成、对侧记录里有素材，不等于本侧当前任务已经收到可合成字节。
6. 本侧缺能力或素材时，通过已注册的跨侧工具请求查询、分析或委托，保留任务关联和全部约束。工作可以从任一侧发起，执行位置由能力决定。
7. 作业或对侧结果到达后读取实际记录，继续原事项。已提交的步骤不重做。长期事项完成一期后仍可等待下一期。
8. 每次文件交付说明来源与模拟边界。没有视觉分析能力不声称理解画面，没有物理驱动不声称移动了设备。实际工具schema决定支持的规格，不能悄悄改变用户要求。

9. 每天播报进展保存为report事项，用set_wake_rule指定时区、时刻与播报位置。登记后等待，到期沿原事项会话查询真实记录并publish_report。明确区别用户备注、模型旧报告与已核验执行结果；没有完成证据就说明未核验。没有TTS时只交付标注模拟的文字通知。

## 候选素材清单统计脚本

需要可靠计数时，把候选元数据存到工作区JSON：
`{"candidates":[{"id":"clip-1","source_ref":"registered-source-1","duration_ms":3000}]}`。
用 `run_skill_script(script="camera-workflow/candidate-summary", input_file="candidates.json")`
调用本Skill的 `scripts/candidate_summary.py`，返回片段数量、不同来源数量及总时长。
它是实际Python子进程计算，不能证明文件存在或视觉质量；媒体真实性仍须媒体工具核验。
脚本只接收这个清单，不接收自由Shell命令；停用本Skill会移除这个脚本能力。

## 采集后继续制作

用户要求先采集/补采再合成时，保存最终有序选段计划并设置 `requires_capture=true`。
先用采集操作；向对侧补采时调用 `peer_request(kind="task", operation="capture", media_recipe=本次采集选段的完整子计划, transfer_result=true, task_id=本事项编号, question=工作说明)`。不能只在question里写采集或传输要求。委托完整制作则明确 `operation="compose"`，沿用最终计划。
完成事件到达后，读取任务和 `media_list`，获得当前事项真实可用的采集 `asset_id`。
调用 `start_job(operation="compose", media_recipe=...)` 时，把对应源选段替换为这个完整采集文件（从0开始，使用完整时长，不再重复裁剪），其余选段及输出尺寸、帧率、静音要求保持原计划。
程序依据采集回执检查来源、顺序和时长；没有采集文件时不能用原片绕过“先采集”的要求。
同一版本同一操作的作业输入一经接受即固定；不要反复改写它。长期事项的本地采集完成会恢复该事项工作对话，继续选择剩余步骤，合成完成后等待下一规则。

只有kind=report的每日文字播报才调用 `read_report_period(task_id=当前事项)`；goal和edit使用触发事件的时间范围及review_observation_period，不能把剪辑任务传给日报工具。日报工具按这次到期编号给出应报道日期与端云核验作业，不按主机此刻的“昨天”猜测。只引用返回的证据ID。每期独立提交 `publish_report`；上期已播不等于本期已播。空记录也应提交本期无可核验记录的说明，不复制旧报告。

## 登记和恢复

用户要求持续观察与自主整理时，用set_wake_rule保存output_kind=review；当前部署默认半小时查看，明确给出的周期优先。模型可只调整下一次查看，不改基础周期。先读取read_recording_policy的实际配置；共享存储由部署统一管理，不用旧独立配额工具覆盖。容量审阅沿已绑定的长期goal工作会话进行，模型决定候选retain/release，原片队列按容量最旧优先回收。判断图和剪辑临时副本用完释放，成片与候选按各自留存策略管理，均计入共享总额。

每小时、每天等周期请求使用kind=goal（文字日报用report）。只从已有文件裁剪，不属于需要现场许可的capture，不设置requires_capture。保存事项本身不执行作业；“现在只登记、到期执行”使用start_paused=false，设置规则后结束本轮。只有明确要求暂停才设置start_paused=true。类型填错时按当前task_id与expected_version修正，不能取消后在同一输入重复创建。
