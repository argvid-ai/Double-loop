# Muse剪辑工作

根据用户目标自主选择素材、片长、镜头、文字、声音和复看方式。用户未指定片长时可以先保存目标，最后由项目时间轴确定片长。结合已交付作品和待办决定是否继续制作。

创作与渲染方法见 [Remotion 官方文档](https://www.remotion.dev/docs/)。这里仅说明Muse的任务、素材与交付接口。用户要求成片或周期交付时包含渲染，后台通过Muse相册和取帧工具检查作品；用户需要交互编辑时再使用官方Studio。

## 任务与素材

- 通过get_task_context和查询工具读取实际任务、候选与作品。list_observation_markers支持分页、连续范围和已用素材记录，查询范围与看图密度由你按目标决定。
- 尚无任务的一次性作品使用save_task(kind=edit)。已有完整任务直接在当前任务制作，不另开剪辑任务。duration_ms仅在用户明确指定时填写。持续任务用begin_media_output登记每条新影片，得到本轮版本后再绑定素材；重试沿同一output_key，失败先修正，不能换任务躲开失败。明确周期视频的触发已登记本轮，读取media_outputs直接继续。
- attach_observation_media把原录像范围登记为本任务的素材，返回asset_id和从0开始的附件时间。inspect_media_frames可读取真实候选或当前成片图片。选择需要的时间位置，短暂动作或切点可加密检查。
- 如实区分实际看过的画面、已有文字说明和未理解的声音。已有转写可以用于讲话字幕。创作文案由你根据画面编写。

## 镜头组织与质量

先确定本期要让用户看见的变化或主题，再选能提供新信息的镜头。长时间固定机位优先比较不同时段、光线和活动，避免把相同全景反复裁切当成新内容。数码裁剪要核对放大后的清晰度和噪点；没有足够细节就保留较宽构图。镜头数量、片长和效果由内容决定，不套固定模板。

复看时检查开头、结尾和切点两侧，确认动作没有无意截断、画面跳切有理由、标题符合实际场景。保留原声时检查音轨连续性与音量变化；未实际听辨不得声称声音自然。文字、转场和音乐只为表达服务，不用堆效果掩盖素材重复。简单选段使用基础配方；需要文字、声音处理或复杂时间轴时使用已安装的Remotion项目，不为普通裁剪另造渲染链。

用户要求完整时段保留时，原片保护优先于候选release。素材“选中”、候选释放、临时副本清理和原片物理删除是不同结果，分别以实际记录说明；不要为了演示删除而破坏仍需保留的原片。

## 编写与执行

Pi原生read_file/write_file/edit_file/bash可用于项目编写、检查和预览。正式渲染通过现有start_job排队，完成事件会继续当前工作，运行时间与并发由部署配置管理。

在工作区建立一个Remotion项目。项目入口应使用registerRoot，作品名称由你选择。项目代码、字体和其他资源都可放在目录内。提交时保存源码快照，node_modules、.git、out、dist不进入快照，依赖使用节点已安装版本。

登记的影音通过asset_ids提供给项目，渲染时挂载为public/<asset_id>.mp4，可用staticFile('<asset_id>.mp4')访问。这些文件由素材工具管理。项目内其他字体、图片或音频资源直接使用相对路径。

提交示例（名称按实际任务填写）：

```json
{
  "task_id": "当前任务编号",
  "operation": "compose",
  "media_project": {
    "directory": "projects/cat-film",
    "entry_point": "src/index.tsx",
    "composition_id": "CatFilm",
    "asset_ids": ["已登记的素材编号"]
  }
}
```

文字、转场、音量、速度和片长写在项目中。基础裁剪也可以继续使用start_job的media_recipe参数。

## 作品检查与交付

制作成功后按内容选择成片画面检查，判断是否满足目标。模型决定需要看多少帧、是否继续查看或修改。工具保存实际取帧的来源、时间和校验记录；图片只在本次调用中使用，不把图片文件或编码复制到持久工作记录。

满意时调用review_rendered_media(action=approve)，notes记录观察到的情况，title单独填写简短内容标题，日期由界面添加。批准成功后用工具返回的asset.uri引用本次视频，网页会显示实际播放器。

需要修改或制作失败时，调用review_rendered_media(action=revise)取得新版本，读取实际错误、修改项目后再次提交。资源预算由部署配置给出。用户明确的要求指导修改，模型可以调整自己选择的构图、效果和渲染方式。

原片位置、项目输入、成片和后续保护状态分别保存。review_observation_candidates可记录素材使用及保护决定，存储回收由已配置策略执行。

用户授权按空间滚动并允许处理后释放时，在成片已保存、复看批准和交付后审阅本期原片。对已处理且无需继续剪辑的候选调用review_observation_candidates(disposition=release)，已使用的范围关联实际used_asset_id，说明释放理由。仍需后续剪辑或用户明确保留的范围继续retain。记录审阅覆盖到的时间和剩余范围，原始判断保留；文件回收由额度策略执行。

容量整理触发时先读取read_recording_policy中的最新usage和本事项候选，复用已有交付及审阅记录。定时整理与容量整理可以沿同一长期事项推进，按需决定补充制作或释放已处理范围。

普通review唤醒可以不出片，不为了完成一次唤醒重复剪旧镜头。临时取段、预览和已完成制作的输入副本由程序在消费者结束后清除；需要时从仍在的原片回读。保留文字配方、来源记录和成片，不通过手动复制素材绕过统一空间管理。
